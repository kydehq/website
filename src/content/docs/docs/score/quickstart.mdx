Three steps: create a key, set the exporter, read the score. No account, no card.

:::tip[Let your agent do it]
Paste `Set up score.kyde.com/skill.md` into your coding agent. It runs these steps for you. See [For agents](/docs/score/agents/).
:::

## 1. Create a key

With a webhook URL for alerts (https only). Kyde posts to it on every band change:

```bash
curl -s https://score.kyde.com/score/v0/keys \
  -H 'content-type: application/json' \
  -d '{"webhook_url": "https://your.app/hooks/kyde"}'
```

Or poll-only, without a body:

```bash
curl -s -X POST https://score.kyde.com/score/v0/keys
```

Both return `{"key": "kyde_…", "method_version": "…", "webhook": …}`. Store the key like a password. It cannot be shown again; if you lose it, create a new one.

## 2. Point the exporter at Kyde

Give every agent its own `OTEL_SERVICE_NAME`. That name is what Kyde scores.

<Tabs>
  <TabItem label="Any OTel SDK">
    Codex, OpenCode, LangChain, your own code: these four variables are the whole integration.

    ```bash
    export OTEL_EXPORTER_OTLP_ENDPOINT=https://score.kyde.com
    export OTEL_EXPORTER_OTLP_PROTOCOL=http/protobuf
    export OTEL_EXPORTER_OTLP_HEADERS="x-kyde-key=<KEY>"
    export OTEL_SERVICE_NAME=invoice-agent
    ```

    Kyde accepts OTLP/HTTP as protobuf or JSON. `http/protobuf` works from every SDK; `http/json` exists only in the JavaScript ones. Framework agents need a GenAI instrumentation that emits `gen_ai` tool spans; other spans are ignored. Metrics are accepted but not scored.
  </TabItem>
  <TabItem label="Claude Code">
    Split the variables by how they vary.

    **Global, once per machine:** endpoint, protocol, key header and the two telemetry flags. Put them in the `env` block of your user-level `~/.claude/settings.json` (covers terminal, IDE and desktop app) or in your shell profile. They are the same for every agent on the machine.

    ```bash
    export CLAUDE_CODE_ENABLE_TELEMETRY=1
    export OTEL_LOGS_EXPORTER=otlp
    export OTEL_EXPORTER_OTLP_PROTOCOL=http/json
    export OTEL_EXPORTER_OTLP_ENDPOINT=https://score.kyde.com
    export OTEL_EXPORTER_OTLP_HEADERS="x-kyde-key=<KEY>"
    ```

    **Per agent, at launch:** `OTEL_SERVICE_NAME` only. Set it in the command that starts the agent, in a wrapper script (export it, then `exec claude "$@"`), or in the workflow or service unit that launches the agent.

    ```bash
    env OTEL_SERVICE_NAME=invoice-agent claude
    ```

    Never put `OTEL_SERVICE_NAME` into `~/.claude/settings.json`. The settings `env` block overrides the launch environment, so one global name silently merges every agent on the machine into a single baseline, and per-launch names lose without any error. Leaving the name unset is the same trap: Claude Code then reports as `claude-code`, and all agents merge under that default. If you followed these docs before November 10, 2026, remove `OTEL_SERVICE_NAME` from your settings first.

    Claude Code ignores OTel exporter variables in a project's `.claude/settings.json` and `.claude/settings.local.json`.
  </TabItem>
  <TabItem label="Grok CLI">
    Grok CLI needs its own opt-in. Its exporter sends protobuf only:

    ```bash
    export GROK_EXTERNAL_OTEL=1
    export OTEL_LOGS_EXPORTER=otlp
    export OTEL_EXPORTER_OTLP_PROTOCOL=http/protobuf
    export OTEL_EXPORTER_OTLP_ENDPOINT=https://score.kyde.com
    export OTEL_EXPORTER_OTLP_HEADERS="x-kyde-key=<KEY>"
    ```

    Grok CLI always reports `service.name` as `grok-cli` and ignores `OTEL_SERVICE_NAME`, so all Grok CLI agents under one key score as one agent.
  </TabItem>
  <TabItem label="OTel Collector">
    Recommended when telemetry has to be scrubbed before it leaves your network. Add an exporter:

    ```yaml
    exporters:
      otlphttp/kyde:
        endpoint: https://score.kyde.com
        encoding: json
        headers:
          x-kyde-key: <KEY>
    ```

    You can delete or hash attributes in the Collector first. Kyde still scores.
  </TabItem>
</Tabs>

## 3. Read the score

Run the agent once, then:

```bash
curl -s https://score.kyde.com/score/v0/scores -H "x-kyde-key: <KEY>"
```

The agent shows up with `"status": "learning"` and a `runs_seen` count. After 30 runs it switches to `"status": "scored"` with a `score` and a `band`. There is nothing to configure for that.

The integration is done when your agent's own `service.name` appears here with `runs_seen` of at least 1. A created key or an active dashboard alone is setup, not an integration. Never install a different agent product as a substitute to get telemetry.

**Nothing listed?** Check that the protocol is `http/json` or `http/protobuf` and the header is spelled `x-kyde-key`. The [skill](https://score.kyde.com/skill.md) has a curl smoke test that sends one record under a throwaway service name, so it never enters a real agent's baseline.
**`degraded` in the response?** Records were dropped because of a limit. See [Limits](/docs/score/limits/).
